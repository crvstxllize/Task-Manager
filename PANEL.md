# Локальная панель развёртывания

Тема аттестации — «Разработка системы контейнеризации и автоматического развертывания веб-приложения с использованием Docker».

## Запуск на MacBook

Нужны Docker Desktop с Compose, Git и Python 3.9 или новее. Панель использует стандартную библиотеку Python. В Terminal после перезагрузки выполните:

```sh
cd "$HOME/Desktop/Task M"
git switch feature/local-deployment-panel
open -a Docker
until docker info >/dev/null 2>&1; do sleep 2; done
docker start devops-task-manager-web-1
python3 -m panel
```

Оставьте Terminal открытым. [Панель](http://127.0.0.1:8000/) работает отдельным процессом, [Task Manager](http://127.0.0.1:5000/) — в контейнере. Команда `docker start` предназначена для уже существующего контейнера на этом Mac. Если контейнер был удалён, но именованный том сохранился, запустите панель и нажмите «Развернуть». При завершении панели нажимайте Ctrl+C после окончания текущего запуска.

## Что происходит при развёртывании

- Кнопка запрашивает актуальный SHA ветки main и проверяет в GitHub Actions последние результаты `ci.yml` и `docker-test.yml` для этого SHA. Монитор выполняет ту же проверку автоматически при старте и каждые 240 секунд. Учитываются только прогоны push в main данного репозитория. Идущая, отсутствующая или неуспешная проверка блокирует развёртывание.
- Очередь, этапы и вывод команд хранятся в `instance/deployment/panel.sqlite3`. Один исполнитель обрабатывает запуски по порядку. После неудачной автопопытки можно повторить запуск кнопкой. Успешный ручной откат позволяет монитору снова обновить приложение. При перезапуске панели прерванное выполнение помечается ошибкой, очередь сохраняется.
- Исполнитель повторно проверяет CI, клонирует только этот репозиторий во временную папку, проверяет принадлежность SHA истории main и переключается на точный коммит. Перед сборкой сверяются порт, метки Compose и том. Используются Dockerfile и compose.yaml из выбранной ревизии. Успешная сборка разрешает замену сервиса web. Проверка готовности использует существующий scripts/healthcheck.py и требует полного совпадения SHA.
- Для публичного репозитория авторизация обычно не требуется. При ограничениях GitHub API можно передать `GITHUB_TOKEN` в окружении процесса панели. Браузер получает только данные о проверках. Команды сборки запускаются с отдельным окружением.

## Показ за 60 секунд

| Время | Действие |
|---|---|
| 0–10 с | Открыть панель и приложение. Показать версию 1.1.0, SHA и задачу, отметить независимые порты 8000 и 5000. |
| 10–25 с | В панели выбрать ручной запуск №2. В логе показать сборку, затем замену контейнера и проверку SHA. Для живой повторной сборки актуального main нажать «Развернуть». |
| 25–45 с | Выбрать автоматический запуск с ebc146d. Сравнить ID контейнеров до и после и одинаковое имя тома. Открыть приложение и показать сохранённую завершённую задачу №2. |
| 45–60 с | Показать две проверки push в main и выполнить команды ниже. Длительность новой сборки зависит от сети и Docker-кэша, история доступна сразу. |

```sh
curl -fsS http://127.0.0.1:5000/health
curl -fsS http://127.0.0.1:5000/version
docker inspect devops-task-manager-web-1 --format '{{.Id}} {{(index .Mounts 0).Name}}'
curl -fsS http://127.0.0.1:8000/api/state | python3 -m json.tool --no-ensure-ascii
```

Для отдельного повторения исторического перехода остановите обычную панель после завершения работы. Запустите из корня репозитория:

```sh
python3 -m panel --manual-sha 98de307d034bebd926ee89e36c9da6c9b4b1bb93 --poll-seconds 90
```

Кнопка теперь указывает выбранный исторический SHA. Нажмите её один раз, дождитесь успеха, добавьте и завершите отдельную задачу на 5000. Оставьте панель открытой. На следующем опросе она обнаружит актуальный проверенный SHA и запишет второй запуск с источником «автоматически». Затем вернитесь к обычной команде `python3 -m panel`. Для обоих режимов используется существующий проект `devops-task-manager` и том `devops-task-manager_sqlite-data`.
